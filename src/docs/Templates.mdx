# Шаблоны заданий

Шаблон — повторяемая визуальная структура задания. Изменение текста, числа или
языка само по себе не образует новый шаблон, если layout и сценарий ответа
совпадают.

## Обзор

### Главное правило

**Одна UI-структура — один шаблон (`templateId`).**

*Как из кучи задач получается один проверяемый экран*

### Как задача превращается в экран

С сервера приходит описание задания: тип, текст условия, поля ответа. По этим
данным выбирается домен (текст, формула, таблица…) и конкретный вариант
раскладки. У варианта есть свой идентификатор шаблона — одна и та же структура
экрана для многих разных текстов задач. Дальше подгружается компонент UI и его
stories для проверки в Storybook.

Домены лежат в `src/modules/tasks/ui/templates/`: text, formula, equation,
answer-cell, column-operation, table, test, comparison, complex. В каждом —
свои правила «какой layout выбрать» и диспетчер UI.

Важно не путать **структурную группу** из данных (вроде `text_2`) с
**идентификатором шаблона** на экране: несколько групп могут рисоваться одним и
тем же UI.

### Какие файлы данных нужны у варианта

Рядом с компонентом обычно лежат небольшие JSON-файлы для stories:

- `data/task.json` — одна каноническая задача для обычного вида и режима решения;
- `data/groups.json` — набор раскладок / групп для экрана «все варианты»;
- `data/all-tasks.json` — по желанию каталог реальных задач класса.

Внутри JSON — id, тип описания, текст или layout условия, поля ответа, переводы.
Точная форма зависит от домена; ориентир — README этого варианта.

### Как шаблон попадает в живое приложение

Сначала в главах классов (`grades`) заданию сопоставляют идентификатор шаблона.
Скрипт собирает белый список заданий, которые хост имеет право открыть новой
модалкой, и кладёт его в `dist/`. Хост импортирует этот список. Задание вне
списка уйдёт в старый UI, даже если компонент уже есть в библиотеке.

### Из чего состоит папка варианта

Обычно это точка входа, сам компонент, данные для stories, файлы stories и
тестов, README с человеческим описанием. Имена вроде `multi-*` или `inline-*` —
это **отдельные** варианты раскладки, а не «флаги» одного и того же экрана.

### Как добавить новый шаблон

Соберите UI, README и примеры данных. Зарегистрируйте идентификатор и ленивую
загрузку. Добавьте правило классификации и тест на него. Если домен ведёт
манифест реализованных шаблонов — обновите его. Обновите `groups.json`,
пропишите задания в главах классов и пересоберите белый список. Проверьте в
Storybook обычный вид, решение, тренажёр и все раскладки.

### На что обратить внимание

Структурная группа в отчётах статистики — не то же самое, что id UI. Манифест,
код и белый список могут расходиться — смотрите покрытие в Statistic. Пока
домен не до конца перенесён, рантайм ещё может брать старые шаблоны.

Живое покрытие — в панели **Statistic → Главная → Покрытие**.

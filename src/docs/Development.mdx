# Работа со Storybook

Storybook — это стенд, где можно смотреть интерфейс модалки, сравнивать варианты
шаблонов и проверять поведение тренажёра **до** того, как запускать всё учебное
приложение целиком. Здесь удобно согласовать, как должно выглядеть задание, не
лезя каждый раз в код хоста.

Порядок работы:

1. Запустить `pnpm storybook` и открыть `http://localhost:6006`.
2. Базовые компоненты — **Design System / UI**.
3. Задания — **Templates**: Default, With Solution, Groups.
4. Поведение проверки — **In Trainer**.
5. Регрессии — runners в **Testing**.

Изолированный стенд модалки без Storybook: `pnpm dev` (`http://localhost:5173`).
Проверка внутри хоста описана в
[Deployment](?path=/docs/documentation-deployment--documentation).

### Как обычно проверяют правку

Сначала меняете код в этом репозитории (компонент, шаблон или текст
документации). Потом открываете Storybook на порту 6006 и смотрите, как
выглядит экран и что написано в docs. Если нужно увидеть то же самое уже
внутри учебного приложения, отдельно собираете библиотеку в папку `dist/`
(удобно держать `pnpm build:watch`) и перезагружаете хост на порту 8888.

```bash
pnpm install
pnpm storybook
pnpm build        # один раз собрать dist/
pnpm build:watch  # пересобирать dist/ при каждой правке
```

### Зачем Storybook умеет открываться без всего приложения

Storybook должен показывать экраны модалки и статистику, даже когда полный
MathEducator не запущен. Короткие импорты вида `@/…` указывают на код в
`src` этого проекта. Куски соседних репозиториев (статистика, панель хоста)
подключаются отдельно. То, что тянет за собой всё приложение — глобальное
состояние, сетевой API, флаги функций — в Storybook заменено простыми
заглушками в `.storybook/stubs/`. Поэтому страница документации и встроенная
панель статистики открываются сами по себе.

При открытии любой story подключаются формулы MathJax, шрифты продукта и
удобства вроде кнопки запуска сценария. В режиме документации у канвы нет
лишнего внешнего отступа — текст и примеры читаются как обычная страница.

### Как устроены stories шаблонов

Каждый вариант задания описывается привычным для Storybook форматом: метаданные
и отдельные истории (Default, решение, раскладки и т.д.). Текст «зачем этот
вариант» берётся из README рядом с компонентом — его подхватывает общий
помощник, чтобы docs не дублировать руками.

Примеры данных для stories лежат рядом с доменом шаблона (например в папке
storybook внутри `text`). То, что пользователь делает мышкой и клавиатурой,
пишется в сценарий `play` у story. Юнит-тест проверяет логику и данные, а не
повторяет те же аргументы story один в один.

История «In Trainer» показывается без внутренних отступов Storybook — чтобы
экран был ближе к тому, как задание выглядит в тренажёре.

### На что обратить внимание

Кнопки запуска сценария и автоматические `play` работают на вкладке **story**,
а не на вкладке чистой документации. Если открыта только docs-страница без
компонента, в рамке preview может быть пусто — это нормально: страница
читается как текст слева в сайдбаре.

При быстрой смене экранов MathJax иногда ругается на незавершённый набор
формул; в preview такие ошибки глушатся, чтобы не засорять консоль.

Если переименовали страницу документации, обновите закладки в браузере и
порядок в сайдбаре — иначе старые ссылки могут вести в никуда.

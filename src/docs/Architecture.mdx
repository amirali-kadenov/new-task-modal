# Архитектура интерфейса

Страница описывает визуальные зоны модалки и границы модулей для интеграции с
хостом. Модалка объединяет условие задания, ввод ответа и вспомогательные
инструменты в одном сценарии.

1. границу между условием и ответом;

3. изменения после проверки (ошибка, успех, решение);
4. поведение при длинном тексте, переводах и узкой ширине;
5. необходимость полного контекста Trainer, Canvas или Chat.

### Как модалка появляется на странице

Учебное приложение не встраивает модалку внутрь своего React-дерева как обычный
компонент. Оно создаёт отдельный «островок» React внутри элемента
`#task-modal-wrapper` на странице урока. Контроллер библиотеки может вызываться
снаружи React хоста и сам ничего не рисовать в дереве хоста — это ожидаемо: он
поднимает свой root и показывает UI там.

Типичный путь такой. Хост лениво подгружает библиотеку, передаёт задачу, белый
список и колбэки. Контроллер подключает шрифты, создаёт root, поднимает
хранилище сеанса и запросы. На экране собирается каркас модалки, а внутрь
подставляется нужный шаблон задания. При закрытии хост просит закрыть модалку, и
root снимается.

### Что хост обязан передать

Полный список полей описан в типах
`src/modules/task-modal/model/types/props.ts` и `actions.ts`. Смысл такой:

- **задача** — что сейчас решает ученик;
- **зависимости** — как ходить в API, переводить строки, показывать тосты,
  работать с сокетом урока, хелперами и флагами;
- **состояние сеанса** — список задач, загрузка, флаги решения и видео, прогресс;
- **действия** — проверить ответ, следующее / предыдущее, показать решение или
  видео, теория, смена ответа;
- **данные урока** — идентификаторы, прогресс пользователя, роутер, признаки
  мобильного;
- **закрытие** — как убрать модалку;
- при необходимости — отрисовать старый UI внутри нового контейнера.

Без элемента `#task-modal-wrapper` в DOM монтировать некуда.

### Как выбирается шаблон

Сначала смотрим на текущую задачу. Если для неё есть явный override в карте
структурных задач — берём указанный шаблон. Иначе по типу задания идём в карту
доменов и правила классификации внутри домена (текст, формула, таблица и т.д.)
и получаем UI-вариант, который подгружается лениво.

### Что происходит при проверке ответа

Пока ученик вводит ответ, экран в спокойном состоянии. После «Проверить» идёт
ожидание ответа сервера. При успехе можно открыть решение (поля только для
чтения) или перейти дальше / закрыть. При ошибке — снова ввести ответ или
посмотреть разбор. Это логика экрана; детали API остаются на стороне хоста.

### Из чего состоят зависимости

Зависимости нужны, чтобы модалка говорила с живым приложением: HTTP и команды
урока, realtime по сокету, переводы и глобальный контекст хоста, тосты и алерты,
хелперы чисел и направлений письма, опциональные флаги функций. Без них шаблон
на стенде можно показать на заглушках, а в продукте — нет.

### Куда смотреть в репозитории

Вход библиотеки — `src/index.ts`. Монтирование — в controller модалки. Контракты
пропсов и действий — в `model/types`. Состояние сеанса — Zustand store. Override
и карта типов — в `structural-task-map` и `template-map`. Сами UI-варианты — в
`templates/{домен}/`. Привязка заданий к шаблонам по классам — в
`ui/grades/`.

### На что обратить внимание

Нет `#task-modal-wrapper` — экран не появится. Хост может попросить нарисовать
старый UI внутри нового контейнера через `renderLegacyTask`. Конфликт версии
при сохранении ответа отражается в состоянии сеанса. Выбор новой или старой
модалки на хосте зависит от `?old` и белого списка — см.
[Deployment](?path=/docs/documentation-deployment--documentation).

Ленивая загрузка, стили, task container, математика и полный цикл шаблонов —
[Internals](?path=/docs/internals-обзор--documentation)
([технический цикл шаблонов](?path=/docs/internals-шаблоны--documentation)).

Подробнее о продуктовых правилах шаблонов:
[Templates](?path=/docs/documentation-templates--documentation).

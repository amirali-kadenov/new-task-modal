# 🗺️ Маппинг заданий по классам и главам (Grades Mapping)

Обзор механизма определения шаблона задания на основе учебной программы.

---

## 🎯 Принцип определения шаблона

В платформе задания обозначаются идентификаторами вида:
`Task_<Класс>_<Глава>_<НомерЗадания>_<Суффикс>` (например: `Task_4_2_10_1`).

Поскольку сервер Phoenix передает сырые данные задания, выбор UI-шаблона рендеринга производится клиентом на основе конфигурационных файлов в `src/modules/tasks/ui/grades/`.

---

## 📂 Структура конфигурации

```text
src/modules/tasks/ui/grades/
├── grade-4/
│   ├── chapter-1.ts
│   ├── chapter-2.ts
│   └── ...
├── grade-5/
│   ├── chapter-1.ts
│   └── ...
└── index.ts               # Реестр маппингов для всех классов
```

---

## 📄 Пример файла главы (`chapter-1.ts`)

Каждая глава экспортирует объект, где ключом является тип шаблона `TemplateTypes`, а значением — массив суффиксов номеров заданий:

```typescript
import { TemplateTypes } from '../../model/template-types'

export const chapter1 = {
  [TemplateTypes.Text]: [
    '1_1', '1_2', '2_1', '3_1'
  ],
  [TemplateTypes.AnswerCell]: [
    '4_1', '4_2', '5_1'
  ],
  [TemplateTypes.ColumnOperation]: [
    '6_1', '6_2'
  ],
}
```

---

## 🔍 Логика резолва

При открытии задания резолвер `getTemplateTypeByTaskId(taskId)`:
1. Извлекает класс и номер главы из `taskId`.
2. Находит нужный конфигурационный файл главы (например, `grade-4/chapter-1.ts`).
3. Сопоставляет суффикс `taskId` с массивами в конфигурации.
4. Возвращает соответствующий `TemplateTypes`.

Если задание не найдено ни в одной из конфигураций, применяется дефолтный шаблон `TemplateTypes.Text`.
